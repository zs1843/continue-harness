# Specialized implementation paths

The repository retains implementation areas for specialized checks and generation. They are not prerequisites for the common Harness workflow or definitions of the default project structure; the directories themselves do not form a plugin protocol for dynamically registering arbitrary adapters.

## Usage principles

- Confirm project facts, task goals, and acceptance needs first.
- Enable a specialized capability only when a concrete need exists.
- Configuration, code, and real-project evidence jointly define its boundary.
- Document scope, unconfigured states, and unverified areas.
- Do not infer that a project has a capability merely because a specialized implementation exists in the repository.

Core maintains common collaboration records, verification orchestration, and traceability. The project remains responsible for authoritative facts, implementation choices, and check commands. Specialized capabilities do not replace acceptance links or confirmation of project facts.
