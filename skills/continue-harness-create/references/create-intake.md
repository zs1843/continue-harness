# 创建问答

仅在上下文中没有答案时询问。同一阶段缺少多项必要事实时一次性列出，避免逐项开启多轮问答；可安全推断的内容直接处理。阶段结束后按项目对话交接规则给出编号后续操作。

## 创建前必要信息

1. 项目名称与完整目标目录。
2. 会影响脚手架结构且无法从上下文判断的 Profile、Platform 和 Stack。

创建前不要要求 PRD、RP、UI、API 或品牌资产。此时项目输入目录尚不存在，缺少这些文件不是创建阻塞条件。

## 项目生成后的输入确认

1. 先展示 PRD、RP、UI、API、assets 五类输入目录的完整路径，等待用户放置文件。
2. 用户确认文件已放好后，运行 `continue-harness inputs inspect --json`，再确认输入类型、版本和有效状态。
3. API 来源：本地 OpenAPI、Apifox/Swagger 导出，或暂时未提供。密钥只在真正同步时询问，不写入文档和快照。
4. UI 存在时确认它是否为本次视觉依据；存在多个版本时确认有效版本。
5. Design Token 来源：高保真 UI、RP、项目既有 Token、用户明确临时要求，或暂时保持 `pending_extraction`。没有输入时不提前选择视觉值。

## 生成后工程确认

- CI 平台未提供时保留本地门禁，不擅自创建远程服务。
- 本地接口代理缺少目标地址时生成安全的环境变量入口，不写死业务域名。
- HTTP 层使用 uni-app 原生请求能力封装，不引入业务接口。
- 公共方法和组件只提供目录、边界与业务无关基础实现，避免空壳数量膨胀。
- 用户提供 UI 时，在建立视觉基线前不得宣称视觉还原完成。
