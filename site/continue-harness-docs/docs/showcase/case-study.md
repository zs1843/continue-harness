# 项目案例

> 本页总结当前实现及其可复核边界。真实项目最近一次复验见[Pilot 记录](./real-project-pilot.md)。

## 要解决的问题

需求、项目资料、实现记录、检查结果和交接上下文容易分散在不同位置。接手者可能无法确认哪些事实有效、为何作出决策、某项需求是否已有验收证据，或验证结果是否对应当前变更。

Continue Harness 将这些关系纳入同一协作流程。Harness 负责记录、关联、验证编排和上下文恢复；项目仍负责业务判断、权威资料和实际检查定义。

## 当前能力与边界

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 创建与接入 | 预览计划并准备约束和协作记录 | 不生成业务实现；升级与冲突补丁尚未建立 |
| Intake 与输入 | 保存项目事实、输入来源、适用性和变化状态 | 分析可能需要人工解释 |
| 任务与恢复 | 维护任务标识、历史、快照和交接上下文 | 记录质量取决于确认事实是否及时维护 |
| 验证与验收 | 执行项目声明的检查，并校验需求到验收的关联 | 命令通过不证明业务正确；未收口项会阻止通过 |
| 日志与报告 | 保存命令结果、状态和证据引用 | 敏感数据不得进入日志 |
| 专项实现路径 | 为明确的项目需求提供单独能力 | 不是动态插件协议；每项能力须以自身实现和验证证据界定，不自动适用于所有项目 |
| Agent 协作 | 约束入口与可调用工作流 | 实际效果和效率提升尚无量化结论 |

## 真实项目验证

2026-10-09 的两项 Pilot 均在新验收门禁下 Audit failed。项目事实确认、输入分析和项目检查通过，但验收关联仍有缺口；Doctor 发现环境文件忽略规则缺失，且 Agent 约束文档未说明输入登记流程。该结果支持“门禁能暴露未闭环记录”，不支持“两个项目已完成交付”。

详细证据、重跑方法和未决事项见[真实项目 Pilot](./real-project-pilot.md)。历史通过结果不代表当前门禁下通过。

## 设计原则

1. **项目事实归项目所有。** Harness 不猜测需求、输入或检查方式。
2. **写入先预览。** 创建和接入先检查目标，避免静默覆盖。
3. **证据与结论绑定。** 报告、输入和验收项要对应当前任务及变更。
4. **未配置不等于通过。** 未知、延期、失败与阻塞保留不同状态。
5. **交接应可恢复。** 新接手者应能从持久记录恢复当前事实、风险和下一步。
