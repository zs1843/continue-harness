# `demo-h5`：从 PRD 到可审计证据

本页记录 `demo-h5` 当前已经验证的事实，以及业务验收完成后需要补充的证据类型。它不是业务页面完成报告，也不把计划中的结果描述为已通过。

## 已验证事实

2026-09-21，项目已登记 T001《入境游 AI 行程助手 PRD》。PRD 描述路线搜索与比较、逐日行程、天气事实与提示、独立对话、变更预览与撤销等需求。执行 `continue-harness inputs inspect --json` 后，记录得到以下结果：

| 事实 | 结果 | 证据含义 |
| --- | --- | --- |
| PRD 输入 | `PRD-T001` 已登记 | 需求输入已进入 Harness 输入清单 |
| 文件完整性 | 哈希未变化，`changed: false` | 已登记文件与当前文件内容一致 |
| 输入检查 | `issues: []` | 本次输入检查未发现登记问题 |
| 需求状态 | `draft` | 输入仍是草稿，不能解释为业务验收通过 |

上述结果只能证明输入登记和完整性检查已执行。业务页面、覆盖矩阵和业务交互验证尚未完成，因此本页不对业务功能完成度作出结论。

## 业务验收所需的证据

业务实现完成后，应为 PRD 第十一章中的每条验收剧本登记对应的实现、验证结果和报告路径。证据至少应覆盖以下内容：

| 验收范围 | 应记录的证据 | 验收结论 |
| --- | --- | --- |
| 路线比较 | 查询条件、候选路线、取舍理由及示例数据来源 | 由实际功能验证报告确认 |
| 行程详情与天气 | Day 1–3、天气模式、来源、时间，以及事实与建议的区分 | 由实际功能和数据降级验证确认 |
| 对话调整 | 原活动、建议活动、应用操作、保留原方案和撤销结果 | 由实际交互验证确认 |
| 覆盖与验证 | 覆盖矩阵节点、验证命令、报告路径和阻塞记录 | 由任务验收记录确认 |

视觉基线未配置时，视觉检查应记录为 `not_configured`，不能记录为通过。任何页面截图只能作为实际验证报告的辅助证据，不能替代命令输出、覆盖记录或验收结论。

## 当前结论

`demo-h5` 当前能够证明需求输入登记、哈希完整性检查和草稿状态可追踪；尚不能证明业务页面、业务交互或视觉验收已完成。后续业务任务应创建新的稳定任务编号，并将输入、实现文件、验证报告和验收结论绑定到该任务。
