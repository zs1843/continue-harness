# 创建问答

先使用当前对话和项目文件中已确认的信息，仅询问缺失或冲突的事实。

## 第一轮：项目事实

确认目标目录、项目目标、范围与非目标、项目类型、运行环境和技术栈。不确定的信息保留 pending，不从已有模板推断。

## 第二轮：任务输入

结合项目事实与任务，提出最小候选输入清单并确认适用原因。界面任务可以需要设计参考；计算逻辑任务可以只需要复现步骤和预期结果；数据任务可以需要字段契约与评估指标。UI、API、Token 均不默认必需。

将用户确认的需求保存为项目文件，在 manifest 登记来源、版本或哈希、类型和任务编号。已有文件直接引用，不强制搬迁。自定义输入通过 intake evidence --id <类型> --note <适用原因> 登记；不适用项说明原因。

## 验收与交接

实现前在 docs/ACCEPTANCE.md 关联需求、实现项与验收标准。执行项目实际配置的验证，保存证据与交接状态；不增加任务无关的工具、远程服务或设计治理。
