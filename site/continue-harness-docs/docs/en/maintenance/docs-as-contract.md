# Documentation maintenance

This page lists the changes that require documentation updates, plus the commands that check the docs build.

## Require an update

- public CLI commands, arguments, output, or default help;
- content generated by `create` or `init`;
- `.continue-harness/project.yaml` schema or configuration semantics;
- Profile, Platform, or Stack capability changes;
- Agent Skill read order or workflow changes;
- Doctor checks, verify modes, or report formats;
- OpenAPI, UI System, or Design Token capability changes;
- current status, limitations, or roadmap changes.

## Do not require an update

- internal refactoring with no behavior change;
- test implementation changes with no user-visible result change;
- spelling, formatting, or local code-style fixes.

## Change practice

Put documentation changes in the same pull request or commit group as the Harness behavior change, so both are reviewed together.

## Build check

```bash
cd site/continue-harness-docs
pnpm docs:build
```

Run `pnpm install` first if dependencies are not installed; run the workspace tests with `pnpm test` before publishing.
