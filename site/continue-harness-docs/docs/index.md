# Continue Harness

可恢复的项目协作与质量 Harness

需求 → 实现项 → 验收项 → 证据 → 交接状态

通过对话确认项目事实，按任务选择必要依据，以可验证的标准组织实现，并保存可恢复的项目上下文。

## 为什么使用 Harness

项目需求、实现和验证记录容易分散在不同文件与会话中。接手者需要重新辨认哪些事实有效、哪些结论已验证、哪些事项仍未完成。

Continue Harness 将这些关系保存在项目内。Agent 可以沿着同一组任务、输入和验收记录继续协作，工程验证结果也能关联到具体证据。

## 开始使用

在支持 Skill 的 Agent 中打开项目，并按[开始使用](/guide/getting-started)中的提示发起协作。根据当前阶段调用已有操作 Skill；不需要安装聚合项目 Skill。Agent 将恢复现有记录，或通过多轮对话确认项目基本信息；之后根据任务登记依据、维护验收关系、运行项目已有检查并准备交接。

创建新项目与接入已有项目使用同一套通用工作流。项目代码结构和验证方式依据项目自己的事实确定。

## 当前能力与边界

| 能力 | 当前行为 |
| --- | --- |
| 项目事实 | Intake 按轮次确认目标、范围、环境和协作约定；未确认内容保持待处理 |
| 输入依据 | 登记来源、版本、任务关联和文件变化；类型由项目和任务决定 |
| 验收关系 | 检查需求输入、实现项、验收标准及本地证据的记录关联 |
| 验证报告 | 运行项目配置的命令，并关联任务、输入、实现、证据和验证配置 |
| 上下文恢复 | 汇总项目事实、输入、任务、日志、决策、验收及最近验证状态 |
| 交接快照 | 保存交接时的项目上下文和验证报告副本 |

自动检查验证登记关系与文件状态，不评判需求是否完整，也不能替代对业务结果的审查。需求拆分和证据充分性仍由项目协作者确认。

## Pilot 结果

2026-10-09 使用当前源码复跑两个真实项目的 T001：两边配置的工程检查均通过，但 Audit 均因旧验收记录缺少任务、需求、实现和证据关联而失败；Doctor 发现环境文件忽略规则缺失，且 Agent 约束文档未说明输入清单流程。快照均因验收未闭环而被阻止。详见[真实项目 Pilot](/showcase/real-project-pilot)。

自动化回归覆盖核心流程；Site 构建检查覆盖中英文页面。实际结果和边界见[项目案例](/showcase/case-study)。
