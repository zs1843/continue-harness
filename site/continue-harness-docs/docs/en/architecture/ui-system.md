# Optional visual and component records

Visual references, component policies, and design values are optional inputs. The common Harness workflow does not require them; include them only when confirmed project facts or acceptance criteria make them relevant.

Some repository modules can inspect structured records for flows, layout, adjustments, or component inventories. These specialized paths must be explicitly configured and verified against their intended evidence. Their existence does not imply a default dependency, automatic design decision, or universal project support.

## Evidence and ownership

The project owns its source materials, confirmed design decisions, component policies, and accepted exceptions. Generated inventories and candidate values are provisional until reviewed. Passing a protocol fixture does not establish visual or interaction acceptance in a real project.

## Boundary

Without a confirmed source and reviewable baseline, report the capability as unconfigured or unverified. Do not claim visual fidelity from unrelated checks, and do not add visual or component records to projects where they do not apply.
