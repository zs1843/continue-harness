# 设计原则

Continue Harness 让项目事实、需求、实现、验收、证据与交接状态保持关联。通用记录和门禁由 Harness 提供；业务判断、权威输入和实际检查方法由项目负责。

## Core 与项目边界

Core 维护配置、Intake、输入登记、任务历史、上下文恢复、验证编排、验收检查、报告和日志。它不定义项目的业务页面、领域状态、品牌或需求结论。

项目配置归项目所有，记录已确认的事实、相关输入和项目实际执行的检查。Harness 不根据单一项目样例推断其他项目的结构。

## 初始化安全

接入已有项目时，先预览写入计划。初始化保留已存在的文件（包括项目修改过的文件），并逐个创建缺失文件；写入失败或并发变化可能留下部分结果。

```bash
continue-harness init --dry-run
```

## 按需启用能力

默认工作流覆盖项目事实、输入、任务、日志、上下文恢复和验收。其他输入与检查仅在任务需要且项目已确认时启用。可选能力不改变通用闭环，也不构成所有项目的必填项。

## 验证是证据，不是业务判断

报告记录已配置检查、结果和阻塞原因。未配置、失败、环境阻塞和通过是不同状态。命令成功不自动代表需求已完成；需求需要关联实现项、验收标准和可复核证据。

## 约束与审批

`AGENTS.md` 是项目约束的唯一权威来源。宿主入口文件可指向该来源；Skills 描述可调用流程，不复制或覆盖约束。

发布、依赖升级和公共协议变更需要显式确认。
