# Project record templates

Creation and adoption workflows prepare project constraints and collaboration records. The default content captures project facts, input sources, tasks, acceptance, logs, and handoff context; it does not include predefined business implementation.

## Record categories

- Project constraints and Agent entry points.
- Project goals, current status, and durable decisions.
- Intake state and input manifest.
- Task history, acceptance items, and handoff snapshots.
- Command records and verification reports.

The creation or adoption plan lists the files to be written. Existing project files are checked for ownership and conflicts; project-owned content is not overwritten by default. Optional records are included only when project facts and task scope show they are relevant.

## Creation boundary

Creating a project prepares constraint and collaboration containers. It does not create business pages, domain states, interface implementations, or other project code. Adoption reuses existing facts and documents where possible to avoid duplicate records.

## Capability boundary

Templates describe information responsibilities, not a fixed directory inventory or complete project structure. The plan and execution result are authoritative for target paths and generated content. The presence of a record container does not mean its facts are confirmed or its acceptance evidence is complete.
