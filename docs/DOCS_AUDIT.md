# 文档与实现一致性审计

更新日期：2026-10-09

## 审计目标

检查 README、仓库维护文档和中英文 Site 是否准确描述当前 Harness 的通用工作流、实现能力及边界。文档只描述由代码、测试或可复现记录支持的行为；历史专用实现不作为通用能力或默认项目模型。

## 当前结论

- 核心叙事统一为：项目事实 → 适用输入 → 需求 → 实现项 → 验收项 → 证据 → 交接状态。
- 创建与接入准备约束和协作记录，不承诺生成项目实现。
- 输入根据已确认的项目事实与任务范围选择；任何输入类别都不是所有项目的必选项。
- 验证执行项目配置中声明的检查；未配置、失败、阻塞和通过保持不同语义。
- 验收闭环要求任务、适用输入、验收项和证据可追溯；命令成功本身不代表需求已验收。
- 2026-10-09 两个真实 Pilot 的 Audit 均为 failed。文档保留这一结论，不沿用旧门禁下的历史通过结果。
- Site 中英文页面保持内容和能力边界一致。

## 本轮修订

- 重写首页、README、架构、配置与文件、验证模式和通用设计说明，移除专用项目形态作为产品叙事主线。
- 把当前 Pilot 的未通过结果作为能力边界证据，区分“门禁能阻止不完整记录”和“项目交付已通过”。
- 对照当前实现修正初始化写入语义、快照前置条件和配置字段；说明专项目录不是动态插件协议，避免将通用流程误写为任意项目形态均已支持。
- Site 主导航统一为“介绍 → 开始使用 → 新建 / 接入”；CLI、Skill 清单和架构细节置于次级参考，不再并列成日常入口。
- 补全 Pilot 复验命令、完整报告哈希、报告指纹和源码摘要，并明确原始报告、命令日志及项目源码快照未随 Site 发布，当前公开摘要不能独立重算哈希。
- 按路径逐页核对 39 组中英文页面，补全 Core 与视觉/组件记录中文页，并检查结构和关键事实对应关系。
- 校正旧路线图、状态说明和项目地图，删除过期测试数量及历史计划。
- 清理仍把可选输入或专用检查描述成默认要求的文字。
- 清理旧生成清单和未复验案例，或将其明确标为历史材料。
- 复核 Skill 归属与输入分析描述，删除不存在的 Intake Skill 和协作工作流入口表述；说明当前 Intake 的候选问题集边界，并避免把可选视觉依据列为通用检查项。

## 审计边界

本审计不表示所有可选代码路径都已验证，也不证明 Harness 已适用于每一种项目。能力声明应同时满足实现存在、反例测试覆盖、文档准确及相关项目证据可复现。后续行为变更应同步更新测试和中英文文档。
